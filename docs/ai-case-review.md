# AI 辅助用例 · 人工评审记录

目的：证明「用 AI 提效测试」有闭环，而不是简历空写熟悉 AI。  
流程：让 AI 按 posts 接口草稿一批边界/异常用例 → 人工对照真实 API 行为评审 → 保留的写进自动化，丢弃的写清理由。

评审日期：2026-10-27（Asia/Shanghai）  
被测：`https://jsonplaceholder.typicode.com/posts`  
已有自动化：正向 7 + 负向/边界 8 = 15（评审前）

## 采纳率

| 项 | 数量 |
|----|------|
| AI 草稿 | 12 |
| 保留并落地 | 2 |
| 修改后保留（语义保留，断言按真实现改写） | 1 |
| 丢弃 | 9 |
| 采纳率（保留+修改） | 3/12 = 25% |

面试可讲：AI 擅长铺场景清单，但对本服务「几乎不校验入参」的事实不敏感；不经评审会写出大量期望 4xx 的假阴性。

## 评审表

| # | AI 草稿（摘要） | 决定 | 理由 | 落地 |
|---|-----------------|------|------|------|
| 1 | GET `/posts?userId=1` 只返回该用户且每条 userId=1 | 保留 | 查询参数过滤是接口回归常见项；本 API 支持 | `test_list_posts_filter_by_user_id` |
| 2 | GET `/posts/1/comments` 200 且评论挂在 postId=1 | 保留 | 关联资源可读，补「不止 posts 本体」 | `test_get_post_comments_for_post_1` |
| 3 | DELETE `/posts/1` 应 200/204 且再 GET 为 404 | 修改 | 演示服 DELETE 常返回 200，但资源不真删；改成「DELETE 非 5xx，且不假定持久删除」 | `test_delete_post_does_not_500` |
| 4 | POST 缺 title 应 400 | 丢弃 | 已知不校验，仍 201；已有 `test_create_post_missing_title_still_201` 文档化真实现 | - |
| 5 | POST title 超长（10k 字符）应 413/400 | 丢弃 | 演示服照收；无稳定上限可断言，易脆 | - |
| 6 | GET `/posts/` 尾斜杠与无斜杠行为一致 | 丢弃 | 对本服价值低，且重定向差异不稳定 | - |
| 7 | PUT 空 body 应 400 | 丢弃 | 不校验；与已有「错误类型仍 201」同类，不重复堆 | - |
| 8 | GET `/posts/1` 响应时间 < 200ms | 丢弃 | 公网延迟不可控，不适合当功能回归门槛 | - |
| 9 | POST SQL 注入字符串应被拒绝 | 丢弃 | 假数据 API 无真实存储/鉴权，安全专项超出本作品范围 | - |
| 10 | GET 无 Accept 头应 406 | 丢弃 | 本服不谈内容协商 | - |
| 11 | PATCH `/posts/1` 只改 title | 丢弃 | 作品范围已用 PUT 覆盖更新；暂不扩方法面 | - |
| 12 | 并发 50 次 POST 无丢失 | 丢弃 | 非功能/性能，两周作品刻意不做 | - |

## 漏测对比（各 3 条）

AI 容易漏、人工补上的：

1. 「假 API 不校验」要写成正向文档化用例，而不是一律期望 4xx。  
2. 失败时打印 status/body 摘要（已有 hook），方便对 CI 日志。  
3. PUT 不存在 id「不能静默 200」比死盯某个 4xx 码更稳。

人工容易漏、AI 草稿提醒到的：

1. `userId` 过滤列表。  
2. `/posts/{id}/comments` 关联读取。  
3. DELETE 在演示服上的「假删除」语义（经修改后保留）。

## 结论

AI 适合发散场景；人工负责对照契约/真实现。本仓库用 25% 采纳率说明筛选过程，比堆未评审用例更经得起追问。
